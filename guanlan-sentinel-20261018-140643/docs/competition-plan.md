# 赛题对照与冲奖验证计划

依据：本目录 `source/赛题九-官方命题.pdf`。本文件是工程验收与后续研究计划，不是获奖承诺。

## 当前交付定位

普通 Windows 电脑上的离线可运行系统。优先完成有证据的输入、可审计的处理过程、资产关联、引用问答和真实界面。实时采集可用性、模型深度推理与大规模准确率必须分别验证。

## 决赛追加验证

- 富化 precision 和 recall 均至少 95%，须有漏检样本统计。
- 问答准确率至少 95%且关联推理可解释。不能用检索召回率替代答案准确率。
- 深度问答和个性化推荐，应与真实资产和用户关注主题关联。
- 多 Agent 自主编排需对照固定流程，证明在成功率、成本或延迟上的改善。
- 容器化、日志、监控和故障恢复需实际运行验证。
- 答辩 PPT 使用主办方模板，并去掉队伍单位、人名等身份信息。

## 建议的独立评测设计

### 富化数据集

由两名队员独立核验至少 100 条 AI 安全公告，覆盖多个产品、风险类别和发布月份，第三人裁决分歧。为产品、版本区间、CVSS、修复版本、资料关系逐项标注证据。开发集与保留测试集按时间和产品族隔离，避免同一漏洞的转载跨集合泄漏。

记录 TP、FP、FN，计算 precision=TP/(TP+FP)、recall=TP/(TP+FN)。对未知值保持未知，不能删除失败样本后重新计算。样本规模由时间预算决定，100 条是建议起点而非已完成数量。

### 问答数据集

准备至少 100 个由人工编写的问题，覆盖单条事实、版本边界、跨文档比较、资产优先级、多跳关联、证据缺失、冲突和恶意文档指令。给出参考答案与必须引用的来源。冻结测试集之后再运行系统，逐题保留输入、输出、模式、模型版本、耗时与引用。

分别比较关键词基线、混合召回、图关联及模型模式。报告答案正确率、引用支持率、拒答准确率与响应时间 P50/P95。高层评分采用人工复核，不能完全依赖同一个模型自评。

### 持续监测实验

连续运行至少 72 小时，记录来源可达率、发布到首次采集的延迟、去重率、错误分类和恢复时间。旧快照时间不能用于证明实时性。API 限流时要保留失败日志，并记录退避后成功结果。

## 交付材料

初赛：Word 与 PDF 技术报告各一份、操作演示视频、技术讲解 PPT 的 PDF 导出。官方说明源代码由企业在参赛平台审阅，不另行单独提交。

决赛：最终技术报告 Word/PDF、匿名答辩 PPT、操作演示视频。主办方模板尚未提供时，可以先完成内容稿，收到模板后迁移，不能将自制模板称为官方版。
