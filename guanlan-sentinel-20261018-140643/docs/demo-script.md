# 现场演示与答辩内容稿

## 演示前检查

运行 `npm test`，启动服务，执行 `npm run evaluate`。确认本地快照可读、界面不请求外部 CDN、浏览器分辨率合适。准备资产样例和离线备份。演示默认使用离线回放，开场明确其性质。

## 五分钟操作脚本

|时间|操作|说明重点|
|---|---|---|
|0:00–0:35|打开情报总览|说明情报来源分散，作品把公开证据与具体资产关联。展示当前数据实际规模|
|0:35–1:15|运行离线回放|展示每个阶段的状态、输入输出、去重与异常记录；说明这是已核验快照回放|
|1:15–2:00|搜索 Ollama CVE 并打开详情|定位公告来源、受影响版本、修复建议与证据哈希。解释哈希用于变化检测|
|2:00–2:45|导入资产清单|比较旧版本与修复版本，展示未知版本需要核验，结论限定于公告|
|2:45–3:40|提问跨产品风险比较|展示检索结果、证据引用与相关资料，逐项打开出处|
|3:40–4:10|询问不存在的漏洞编号|演示系统拒绝编造修复版本|
|4:10–4:40|查看关联图并导出报告|将资料、产品、资产关联呈现给评审，保存本次结果|
|4:40–5:00|说明评测结果与限制|展示真实测试结果，解释本地检索基线及下一阶段独立评测|

## 十页讲解稿结构

1. 观澜：AI 安全知识情报系统。只放项目名称、赛题名称和一句场景说明。
2. 使用问题：公告分散、资产关联耗时、问答结论难核验。用实际工作流程解释，不编造行业数字。
3. 需求覆盖：监测、富化、问答及论文/标准/政策，标明正式赛题来源。
4. 总体架构：数据适配、存储、处理角色、资产关联、问答和界面。
5. 情报处理：用一条真实公告说明字段、去重与来源证据。
6. 资产影响：相同产品不同版本的对照实例。
7. 问答证据：跨文档问题、引用及拒答实例。
8. 任务编排：实际运行轨迹与异常分支。明确当前确定性编排的范围。
9. 实验：展示生成的验证报告，说明样本规模、测量方法与尚未完成的独立评估。
10. 当前能力与研究计划：领域语义召回、多 Agent 自主规划、大样本准确率和连续监测。

决赛须换成主办方模板并匿名，不填写学校、团队成员姓名、指导教师或标识。

## 预期追问

**这与普通检索页面有什么区别？**

回答应结合实机：可追溯资料、版本范围和资产匹配、可观察处理过程、证据引用与拒答。当前离线问答仍是检索基线，不夸大其自主推理能力。

**为什么不直接让大模型回答？**

模型可能缺少最新事实。系统先提供来源可核验的资料，再按模式组织答案。没有模型时仍能核查公告和资产；接入模型后也保留证据及基线对照。

**如何保证准确率？**

说明金标准标注和测试集划分，展示实际结果，不承诺所有问题正确。区分检索命中、引用支持和答案准确率。证据不足时拒答，但也统计拒答造成的覆盖损失。

**知识图谱的边是否都是推理结论？**

不是。产品一致、主题一致和公告影响范围分别是不同边类型；相关性不意味着攻击链或因果关系。展示实际边标签及来源。

**是否自动利用漏洞或扫描互联网？**

当前演示对用户导入资产做静态版本关联，公开验证资料只作链接索引。未经实测的 PoC 不标为已验证有效，也不能把教学资产当成真实互联网发现结果。

**如何证明自主规划有效？**

当前固定工作流可以审计但不能单独证明自主规划。接入规划模型后需要和固定流程做同一批任务的成功率、耗时和工具调用成本对照。
